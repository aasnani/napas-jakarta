# Ground-truth review guide

## Focused 30-question packet

When review time is limited, use `evaluation/gold_review_30_candidates.jsonl`
and the workbook at `outputs/gold-review-30/gold-review-30.xlsx`. The packet
contains exactly 30 machine-suggested rows (15 English and 15 Bahasa
Indonesia) with fixed topic and difficulty quotas. The remaining 120 rows are
listed in `evaluation/gold_review_30_manifest.json` as the development pool
and are not included in the focused retrieval summary.

Every row starts with `review_status=pending_human`. Reviewers should inspect
the proposed chunks and the filtered evidence sheet, then edit the queue with
one of `Approved`, `Corrected`, or `Rejected`. For `Approved` and `Corrected`,
enter exact chunk IDs and a reviewer/date. For `Rejected`, record why the
question or proposed evidence should not be retained. Keep the proposed fields
unchanged so the machine suggestion remains auditable.

Export the six editable columns from the workbook (or create a CSV with these
headers):

```text
question_id,status,human_relevant_chunk_ids,reviewer,reviewed_at,correction_notes
```

The finalizer refuses a missing row, a `Pending` status, an unknown chunk ID or
a missing reviewer/date. After all 30 rows are decided, run:

```bash
uv run python evaluation/finalize_gold_review.py \
  --review-export path/to/review-export.csv \
  --output evaluation/gold_review_30_final.jsonl
```

The final JSONL is the only focused artifact with `review_status=human_reviewed`.
The committed retrieval results remain labelled `provisional_machine_suggested`
until this step succeeds.

The expanded benchmark is generated by `evaluation/build_ground_truth.py` and
contains 150 bilingual questions across ten intent families. Every row is
deliberately marked `seeded_pending_human_review` until a reviewer confirms the
relevant document IDs.

## Review workflow

```bash
make export-review
```

Open `evaluation/ground_truth_review.csv` and inspect each question against the
source passages in `data/docs/`. Keep the proposed IDs when they fully support
the question; add a second ID for questions that genuinely require multiple
sources. Remove an ID when it is only topically related but does not support
the claim. Record uncertainty or an unanswerable question in `notes`.

Fill `reviewed_relevant_document_ids` as a comma-separated list, set
`review_status` to `reviewed`, and add reviewer name/date. Then apply and
validate the decisions without changing the seeded source file:

```bash
uv run python -m evaluation.review_ground_truth \
  --apply evaluation/ground_truth_review.csv \
  --reviewer YOUR_NAME \
  --output evaluation/ground_truth_reviewed.jsonl
uv run python -m evaluation.validate_ground_truth \
  --input evaluation/ground_truth_reviewed.jsonl
```

For source-apportionment questions, confirm that the answer distinguishes an
emissions inventory from receptor/source-apportionment evidence. For policy
questions, confirm instrument type and status. For exposure and high-rise
questions, confirm that the cited source supports advice and limitations rather
than a universal medical or floor-height claim.
